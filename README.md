# コールトラッカー（サーバー版）

リード管理・架電管理システムです。Next.js（アプリ本体）と Supabase（データベース・ログイン機能）で作られており、Vercel という無料のサービスにアップロードして、インターネット上のどこからでもアクセスできるようにします。

このドキュメントは、プログラミングの知識がなくても順番に進められるように書いています。上から順番に進めてください。

### なぜ「さくら」ではなく Vercel なのか（補足）

さくらインターネットのサービス（AppRun や VPS）も検討しましたが、いずれも Docker の操作やサーバーの手動設定（Nginx・SSL証明書など）が必要になり、費用も手間も Vercel よりかかります。Vercel は日本の会社ではありませんが、アプリの実行場所（リージョン）を「東京」に指定できるため、データベース（Supabase・東京リージョン）と合わせて、実質的にすべての処理を日本国内で行う構成にできます。このプロジェクトにはすでにその設定（`vercel.json` で `hnd1`＝東京 を指定）を入れてあるので、追加の作業は不要です。コスト・手間の両方を重視するなら、この構成が最も扱いやすい選択です。

---

## 1. 準備するもの（すべて無料で作れます）

1. **GitHub アカウント** — コードを置いておく場所です。https://github.com/signup
2. **Supabase アカウント** — データベースとログイン機能です。https://supabase.com
3. **Vercel アカウント** — アプリを公開するサービスです。https://vercel.com

いずれも「Continue with GitHub」でまとめて連携させると、以後の作業がスムーズです。まず GitHub アカウントを作り、その GitHub アカウントで Supabase と Vercel にサインアップすることをおすすめします。

---

## 2. このコードを GitHub に置く

1. GitHub にログインした状態で、右上の「+」→「New repository」を選びます。
2. リポジトリ名を `call-tracker-web` などわかりやすい名前にして、「Private」を選択し、「Create repository」をクリックします。
3. この `call-tracker-web` フォルダのファイル一式を、そのリポジトリにアップロードします（GitHub の画面にある「uploading an existing file」からドラッグ＆ドロップでアップロードできます。数が多い場合はいったん zip でも構いません。展開してアップロードしてください）。

※ `.env.local` という名前のファイルがもしあれば、それは絶対にアップロードしないでください（パスワードに相当する情報が入ります。今回のひな形にはまだ入っていません）。

---

## 3. Supabase プロジェクトを作る

1. https://supabase.com にログインし、「New project」をクリックします。
2. プロジェクト名（例: `call-tracker`）と、データベースのパスワードを設定します。**このパスワードは控えておいてください。**
3. リージョンは `Northeast Asia (Tokyo)` を選ぶと日本から速く繋がります。
4. 作成が終わるまで数分待ちます。

### 3-1. データベースの設計図（テーブル）を反映する

1. 左メニューの「SQL Editor」を開きます。
2. 「New query」をクリックします。
3. このプロジェクトに含まれる `supabase/migrations/0001_init.sql` というファイルの中身を**すべてコピー**して、SQL Editor に貼り付けます。
4. 右下の「Run」をクリックします。「Success」と表示されれば完了です。

これで、スタッフ名簿（users）・リード（leads）・架電履歴（calls）などのテーブルと、アクセス権限のルールがすべて作成されます。

### 3-2. 接続情報（URL とキー）を控える

1. 左メニューの「Project Settings」→「API」を開きます。
2. 「Project URL」と「anon public」キーをコピーして、メモ帳などに控えておきます（後で Vercel に設定します）。

---

## 4. Vercel にデプロイする

1. https://vercel.com にログインし、「Add New」→「Project」をクリックします。
2. 先ほど GitHub に作った `call-tracker-web` リポジトリを選び、「Import」をクリックします。
3. 「Environment Variables」の欄に、以下の2つを追加します（3-2 で控えた値を使います）。

   | Name | Value |
   | --- | --- |
   | `NEXT_PUBLIC_SUPABASE_URL` | Supabase の Project URL |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase の anon public キー |

4. 「Deploy」をクリックします。数分でビルドが完了し、`https://（プロジェクト名）.vercel.app` のようなURLが発行されます。これが本番のアプリのアドレスです。

以後、GitHub 側のコードを更新するたびに、Vercel が自動でビルドし直して反映してくれます。特別な設定は不要で、実行リージョンはプロジェクトに含まれる `vercel.json` により自動的に東京（`hnd1`）になります。

---

## 5. 最初のユーザー（オーナー）を作る

新しいユーザーは、アプリの `/login` 画面ではなく、いったん Supabase 側から作成します（サインアップ画面は今回あえて用意していません。誰でも自由にアカウントを作れると困るためです）。

1. Supabase の左メニュー「Authentication」→「Users」を開きます。
2. 「Add user」→「Create new user」をクリックします。
3. あなた自身のメールアドレスとパスワードを入力し、「Auto Confirm User」にチェックを入れて作成します。
4. 次に「SQL Editor」で、以下の SQL を実行します（`your@email.com` の部分を、今作ったメールアドレスに書き換えてください）。

```sql
update public.profiles
set is_owner = true, role = 'admin'
where email = 'your@email.com';
```

これで、あなたが「オーナー」になりました。Vercel で発行されたURLにアクセスし、今作ったメールアドレスとパスワードでログインできます。

---

## 6. スタッフを追加する

橋本さん・石井さんなど、他のメンバーも同じ方法で追加します。

1. Supabase の「Authentication」→「Users」→「Add user」で、そのメンバーのメールアドレスと**仮のパスワード**を設定します（「Auto Confirm User」にチェック）。
2. 決めた仮パスワードを、ご本人に伝えます（本人はログイン後、必要であればアプリの外で Supabase のパスワードリセット機能を使うこともできますが、当面は共有したパスワードでそのままお使いいただく形で問題ありません）。
3. アプリにログインした後、オーナーであるあなたが「メンバー管理」画面から、そのメンバーの表示名やロール（管理者・チームリーダー・スタッフ・ゲスト）を設定してください。

新しく作られたユーザーは、最初は自動的に「スタッフ」ロールになります。

---

## 7. 日々の使い方

- **リード一覧**: 会社名・電話番号・メールアドレスで検索、ステータスや担当者で絞り込みができます。
- **リード詳細**: 会社情報の編集、担当者の変更、通話記録の追加（結果・メモ・次回架電予定・アポ獲得フラグ）ができます。通話を記録すると、リードのステータスと最終架電日時が自動的に更新されます。
- **CSVインポート**（管理者・チームリーダーのみ）: 列名「会社名, 都道府県, 住所, 電話番号, メールアドレス, URL, 元CMS, 業種, 業種詳細」に対応した CSV を取り込めます。今回取り込んだ分をまとめて1人に割り振ることもできますし、未割当のままにもできます。電話番号が既存のリードと一致する行は自動的にスキップされます。
- **ダッシュボード・メンバー管理**（管理者・オーナーのみ）: 全体の件数やステータス別・メンバー別の件数を確認できます。メンバー管理では、表示名・ロール・所属チームリーダーを変更できます（オーナーは全員分、管理者は管理者・オーナー以外を変更可能）。

## 9. ローカルで動作確認する場合（任意）

開発者向けの補足です。手元のパソコンで動かして確認したい場合:

```bash
npm install
cp .env.local.example .env.local   # 中身を Supabase の値に書き換える
npm run dev
```

`http://localhost:3000` で確認できます。

---

## 10. 困ったときは

- ログインできない: Supabase の「Authentication」→「Users」で該当ユーザーが存在し、メール確認済み（Confirmed）になっているか確認してください。
- リードが表示されない: 権限（ロール）の設定により、自分に割り当てられていないリードは表示されない仕組みになっています（管理者はすべて閲覧できます）。
- Vercel のビルドが失敗する: Vercel の「Deployments」からエラーログを確認できます。多くの場合、環境変数の設定漏れが原因です。
